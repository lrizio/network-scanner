Network Scanner - User Guide

Find every device on your network, what it is, and which services it exposes.

Use responsibly. Only scan networks you own or have explicit permission to test. Scanning other people's networks may be illegal.

1. What it does

Network Scanner runs a two-step scan and shows the results in a web dashboard on your own computer:

  1. Discovery - quickly finds live devices on your network using ARP, which also reveals each device's MAC address and manufacturer.
  2. Deep inspection - uses Nmap to find each device's open ports, the software and version behind them, its hostname, and a best guess of its operating system.

Nothing leaves your computer. The dashboard is only reachable from the PC running the app.

2. Requirements

ItemDetails

NpcapFree Windows packet driver, needed for ARP discovery and OS detection. Download from npcap.com (also included in the official Nmap installer). Install once; no reboot is usually required.
NmapAlready included in the nmap folder next to the exe. Keep that folder beside NetworkScanner.exe. If it is missing, the app uses a system-installed Nmap instead.
Administrator rightsThe exe asks for them automatically (Windows "Yes/No" prompt). Without them, OS detection is disabled.

3. Setting up

  1. Copy the whole build folder anywhere you like (for example C:\Tools\NetworkScanner). Keep NetworkScanner.exe and the nmap folder together.
  2. Install Npcap from npcap.com if you have not already.
  3. If Windows SmartScreen or your antivirus warns about the exe, that is because it is unsigned and packaged with PyInstaller. Choose More info -> Run anyway, or add an exclusion for the folder.

4. Starting the app

  1. Double-click NetworkScanner.exe and accept the Administrator prompt.
  2. A black console window appears and prints a link such as http://127.0.0.1:5000. Your browser opens it automatically; if not, Ctrl+click the link.
  3. Leave the console window open while you use the dashboard. Close the window to quit.

If port 5000 is busy the app picks the next free one and prints the correct link.

5. Running a scan

  1. Target range - enter the network in CIDR form. The box is pre-filled with your own network (for example 192.168.1.0/24, meaning 192.168.1.1 - 254). Use 192.168.1.50/32 to scan one device.
  2. Scan depth:
    OptionPorts checkedTypical time per device
    QuickTop 100Seconds
    StandardTop 1000Under a minute
    FullAll 65,535Several minutes
  3. Press Start Scan. The status panel shows the current phase (Discovery Phase, Deep Inspection), a progress bar and live counters. Device cards appear as soon as they are found and fill in as each device is inspected.
  4. Stop cancels the remaining devices. Devices already being inspected finish first.

6. Reading the results

FieldMeaning
IP / MACThe device's network and hardware addresses.
ManufacturerLooked up from the MAC address. Private (randomised MAC) means the device (usually a phone or recent Windows PC) hides its real hardware ID on purpose.
HostnameThe device's network name, from DNS or Windows name resolution. Blank if it does not advertise one.
Likely OSNmap's best guess with a confidence percentage. Without Administrator rights it is inferred from service banners only and labelled as such.
Open portsPort number and protocol, state, service name, and product/version when detectable.
Web pageIf a device has an open web port (HTTP/HTTPS), its card shows a clickable link such as http://192.168.1.1, and the port table has a link icon next to that port. Clicking opens the device's own web page (router admin, printer, camera...) in a new tab.

Use the filter box to search by anything (for example ssh, Apple or .42). Export JSON saves the full results to a file.

Device badges: Queued (waiting), Inspecting (Nmap running), Done, Failed (see the message on the card).

7. Limits & safety rules

  • Only private address ranges (192.168.x.x, 10.x.x.x, 172.16-31.x.x) can be scanned, and nothing larger than a /16.
  • ARP only works on your local network segment. For other private subnets the app falls back to a ping sweep, which may miss devices that block pings and will not show MAC addresses.
  • The PC running the scan does not appear in its own ARP results.
  • Devices with firewalls may show few or no open ports. That is normal.
  • The dashboard only listens on 127.0.0.1 and cannot be reached from other machines.

8. Troubleshooting

ProblemFix
"Not elevated" badge in the headerClose the app, then start it again and accept the Administrator prompt.
Warning: Npcap not found / ARP discovery failedInstall Npcap from npcap.com, then restart the app.
"nmap not found" badgeMake sure the nmap folder sits next to the exe (and contains nmap.exe), or install Nmap from nmap.org.
No devices foundCheck the range matches your network (run ipconfig and look at your IPv4 address and subnet mask). VPNs and virtual adapters can send discovery out the wrong interface - disconnect the VPN and retry.
Windows Firewall promptThe app only listens locally; you can click Cancel on the "allow access" dialog.
Antivirus blocks or deletes the exeUnsigned PyInstaller apps and port scanners are commonly flagged. Add an exclusion for the folder if you trust the file.
Console says "Fatal error"Read the message; the most common cause is no free port. Close other copies of the app.
Scan is very slowUse Quick depth, or a smaller range. Full scans of many devices take a long time.

9. Command-line options

Run from a command prompt if you need them:

NetworkScanner.exe --port 8080        # use another port
NetworkScanner.exe --no-browser       # don't open the browser automatically
NetworkScanner.exe --host 0.0.0.0     # listen on all interfaces (NOT recommended: no login)

Set the environment variable SCANNER_ALLOW_PUBLIC=1 to allow scanning non-private ranges, only if you are authorised to scan them.
